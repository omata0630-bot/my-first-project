# 美容サロン 売上・顧客管理の自動化（GAS）

スマレジ（無料プラン）は売上の登録だけに使い、顧客台帳はスプレッドシートで持つ。
カウンセリングフォームの来店とスマレジの取引履歴CSVを、GASが推定で突合する。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `src/Config.js` | シート名・列名・フォームの質問文・CSVの見出しなど（作る人が決める値） |
| `src/Logic.js` | 判断の中身（電話番号の正規化、CSVのまとめ、突合、集計）。シートに触らないのでテストできる |
| `src/Sheets.js` | シートの読み書き・設定・ログ・ロック |
| `src/Forms.js` | `onFormSubmitRouter` / `onCounselingSubmit` / `onReservationSubmit` |
| `src/Import.js` | CSVの読込（`readSmaregiCsv`）、売上取込への保存、突合（`reconcile`） |
| `src/Customers.js` | 顧客台帳の再集計、検索用ファイルの更新 |
| `src/Nightly.js` | `nightlyImport`（毎日2時）とメール通知 |
| `src/Setup.js` | メニュー、`setupSheets`、`installTriggers` |
| `src/Migrate.js` | `migrateLegacy`、`reportMatchAccuracy` |

## 初期設定

1. カウンセリングフォーム（と予約フォーム）の回答先を同じスプレッドシートにし、回答シートの名前を
   `フォーム回答_カウンセリング` / `フォーム回答_予約` に変える。
2. スプレッドシートの「拡張機能 → Apps Script」に `src/` のファイルを貼る（または `clasp push`。`.clasp.json.example` を参照）。
3. スプレッドシートを開き直し、メニュー「サロン管理 → 初期設定：シートを作る」。
4. 「設定」シートを埋める。
   - フォルダID（01_取込 / 02_処理済）、検索用スプレッドシートID、通知先メール
   - D〜E列のコース対応表（スマレジの商品名 → フォームのコース名）。対応表にない商品だけの会計は「対象外」（物販のみ）になる。
5. 「サロン管理 → 初期設定：トリガーを登録」。

## 運用

- バイト：カウンセリングフォームの入力とスマレジの会計だけ。
- 店長：週1回、スマレジの取引履歴CSVを 01_取込 に置く。翌朝メールが来たら要確認の行を直す。
  - 直し方：来店記録の「スマレジ取引ID」に正しい取引IDを入れ、「突合ステータス」を「手動」にする。
  - 会計のない来店（キャンセル等）は、取引IDを空のまま「手動」にする。
  - 「手動」「移行」の行はGASが上書きしない。
- すぐ反映したいときは「サロン管理 → いますぐ取込・突合を実行」。
- フォーム送信の取り込みに失敗したときは、Apps Scriptのエディタで `addVisitFromCounselingRow(行番号)` を実行すると取り込み直せる（同じ行は二重登録されない）。

## 突合のルール

1. 同じ日、まだ紐づいていない来店、コースが対応表で一致
2. 来店（フォーム送信）時刻 ≦ 会計時刻 ≦ 来店時刻＋許容する時間差
3. 候補が1対1 →「自動（一意）」、同じコースで複数 → 時間順に割り当てて「自動（時間順）」
4. その日の売上を取り込み済みなのに会計が見つからない来店、来店に紐づかない会計 →「要確認」
5. 後から返品・取消になった取引は、自動の紐づけを外して「要確認」にする

## 精度の確認（過去1か月分）

1. 「設定」の「移行時に突合する開始日」に1か月前の日付を入れる。
2. 「初期設定：過去データを移行」。開始日より前は「移行」（手入力の金額のまま）、以降は「未突合」になる。
3. 過去1か月分のCSVを 01_取込 に置き、「いますぐ取込・突合を実行」。
4. 「突合の精度を確認」で、ステータスごとの件数と手入力金額との一致数を見る。

## テスト

```sh
npm test
```

Node 18 以上。`test/logic.test.js` は判断の中身、`test/sheets.test.js` は偽のスプレッドシートで取込〜台帳までを通しで確かめる。

## 未確定（実物を受け取ったら合わせる）

- スマレジ取引履歴CSVの見出し → `src/Config.js` の `CSV_COLUMNS`。金額の列が明細の小計か取引合計かで「設定」の「金額の集計方法」を変える。
- 取引区分の値（返品・取消の呼び方）→「設定」の「返品・取消の取引区分」
- フォームの質問文 → `src/Config.js` の `FORM_FIELDS`
- 文字コード → 実ファイルで確認する（Windows-31J → Shift_JIS → UTF-8 の順に試し、見出しが読めたものを使う）
